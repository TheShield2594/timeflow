# Working in this repo

TimeFlow is a Power Apps **Code App** (React + TypeScript + Vite) that tracks
time against projects and tasks and stores it in Microsoft Dataverse. It holds
the company's billable-time record, so a wrong number is worse than a missing
feature — most bugs here are silent and arithmetic.

## Commands

```bash
npm run dev           # Vite dev server; runs on mock data, no Power Apps needed
npm run lint          # ESLint flat config — warnings fail the build
npm run typecheck     # tsc --noEmit
npm test              # vitest, single run   (npx vitest for the watcher)
npm run test:coverage # same, with coverage
npm run build         # tsc && vite build
```

Run **lint, typecheck, test and build** before calling a change done — CI runs
all four and treats warnings as failures. On Linux, `npm install` needs
`libsecret-1-dev` present first.

## The two things most likely to bite you

**1. Dates are local, never UTC.** Never
`new Date().toISOString().split("T")[0]` for a calendar date: `toISOString()` is
UTC, so for users west of UTC "today" flips to tomorrow in the evening and
entries land on the wrong day. Every `YYYY-MM-DD` key comes from the local-clock
helpers in `src/utils/dates.ts`. Related: don't add 24h of milliseconds to move
a day (`addDaysStr` walks the local calendar instead), and don't subtract two
minutes-of-day values to get a duration — on a DST day the answer is off by an
hour, which is exactly the bug in
[#87](https://github.com/TheShield2594/timeflow/issues/87). Durations come from
instants.

The test suite runs in `TZ=America/New_York` (`vitest.config.ts`) precisely so
this class of bug can't hide behind UTC CI machines. Leave it set.

**2. The data layer is mock-or-host, decided in one place.**
`src/services/userService.ts` detects whether `window.PowerApps` is present.
`dataverseService`, `outlookService` and `teamService` each branch on that once
and expose identical semantics either way: real Dataverse through the generated
SDK in `src/generated/`, or a localStorage-backed mock for `npm run dev`.

Components and hooks **never** touch the SDK — they call the services. Keep the
two paths honest with each other: service tests come in pairs, `*.test.ts` for
the mock and `*.host.test.ts` for the host with the SDK stubbed, and a change to
one path usually needs both.

## Layout

```
src/services/    Dataverse / Outlook / team / user / CSV — the only SDK callers
src/hooks/       One hook per file; hooks/index.ts re-exports the main four
src/utils/       Pure functions: dates, gaps, day-bar and calendar geometry,
                 aggregations, ranges, pace
src/contexts/    Toasts, the loaded date range, and the data layer the pages read
src/components/  Pages, shared primitives and UI; tests beside them as *.test.tsx
src/test/        dataHarness.tsx — the contexts a page test needs, over fixed data
src/generated/   Generated by `pac code add-data-source` — never hand-edit
```

Pages read entries, projects and tasks from `useData()`, not from props — not
the nineteen `PageRouter` used to take. Anything a page needs from the data
layer belongs on `DataContext`; only the shell's own concerns (which page,
whether the timer is busy, the timer itself) travel as props. A page test
renders through `renderWithData` rather than by handing the page a data layer
as props.

## The design system, and where it is enforced

The 2026-09 redesign is not a stylesheet you can freehand over. Three of its
rules are asserted by `src/styles.contrast.test.ts` and will fail the build:

- **Two text colours per theme.** `--label` and `--label-secondary` are the
  only colours a reader reads, and both clear 4.5:1 on `--canvas` and
  `--surface`. So do `--accent`, `--danger` and `--warn`.
- **`--decor` never carries text.** It is for bar tracks, dots and empty
  fills. A rule that puts it on something with a `font-size` fails.
- **`--dim-display` is used exactly once** — the 96px idle clock, the one
  place the large-text contrast exemption applies.

Two more that no test can catch, so they are on you:

- **Colour is data.** `--accent` means "you can act here". A project's colour
  means "this project", and appears on that project's dots, bars and blocks
  only. Nothing else in the app is coloured.
- **Depth is earned.** No `box-shadow` on content. A container gets a surface
  only by floating, scrolling independently, or being dismissible, and it gets
  there through `--material` plus one hairline. Never a card inside a card.

Type sizes come from the ten `.t-*` steps, spacing from the 8pt grid (4 is the
only half-step), and every duration, time and count is set in tabular figures —
which `body` does globally, so it can't be forgotten.

## Conventions

- Comments argue for a decision rather than restating the code. Match the
  density and tone of what's already there.
- Reads are filtered **server-side** by Dataverse (`eq-userid`,
  `eq-useroruserhierarchy`). Client-side filtering is never the security
  boundary — see the README's row-security section before touching a query.
- Deleting a task or archiving a project deactivates the record; only time
  entries are hard-deleted. Don't "simplify" that into a real delete — it would
  strip names from historical reports.
- User preferences live in `localStorage` (there is no per-user Dataverse
  store), scoped per environment + user.
